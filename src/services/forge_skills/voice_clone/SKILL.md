# 克隆音色

目标：把用户的一段录音变成**专属音色**，并让这个音色能直接用来创建角色。

## 前提

- 用户上传录音后，用户消息里会出现 `[用户上传了录音]` 标记，格式是
  `audio_key=... | name=... | duration=...s`。**只能使用这里给出的 audio_key**，不要自己编造，也不要复用别的会话的 key。
- 没有录音就没有音色可克隆。如果用户只说了"想用自己的声音"但还没发录音，直接请他发，不要调用任何音频工具。

## 步骤

### 1. 检查录音：`inspect_audio`

传 `audio_key`，可选 `target_seconds`（计划截取多长，默认 10）。返回：

- `duration_seconds`：总时长
- `loudness_db`：音量中位数，太低说明录音太轻
- `quiet_ratio` / `longest_pause_seconds`：静音占比和最长停顿，用来判断哪里是干净的一段
- `suggested_start_seconds` / `suggested_duration_seconds`：建议的裁剪窗口

判断标准：

- 总时长 **少于 3 秒**：无法克隆。告诉用户太短，请录 10 秒以上。
- `loudness_db` 明显偏低（例如低于 -35）：提醒录音太轻、环境可能太吵，但仍然可以尝试，让用户自己决定。
- 其余情况直接进入下一步。

### 2. 剪出干净片段：`crop_audio`

传 `audio_key`，加上 `start_seconds` / `duration_seconds`。

- 默认用 `inspect_audio` 给的建议值；你也可以根据停顿位置自己判断更合适的起点。
- 目标长度 **10 秒左右**（3-30 秒都允许）。太长的录音别整段丢给克隆接口。
- 录音本来就不长（比如 12 秒、没有明显噪音）时可以不传参数，工具会原样返回。
- 返回一个新的 `audio_key`，**后面所有步骤都用这个新的 key**。

### 3. 建音色：`clone_voice`

传：

- `audio_key`：第 2 步返回的新 key
- `display_name`：**必须英文**，2-4 个词，例如 `Warm Narrator`、`My Voice`。用户没指定就自己起一个，不要用中文，也不要直接把文件名当名字。
- `preview_text`：**必须英文**，一句自然的短句，会作为试听音频念出来。不传会用默认英文句。
- `language_hint`：录音主要语言，`zh` 或 `en`；不确定就不传。

成功后工具会返回 `voice_profile_id`，并且音色卡自动展示给用户（播放键 + 波形 + 引号里的试听文案）。**不要在回复里重复描述参数或卡片内容**，用一句短话引导试听即可。

### 4. 收尾

音色卡出来后停下，问用户：

- 试听感觉怎么样，要不要调整（换一段录音重录、或者改用系统音色）
- 要不要就用这个音色创建一个角色

用户同意建角色时，调用 `create_character` 并传 `voice_profile_id`。**不要再传 `voice_base_id`**，两者互斥；传了 `voice_profile_id` 就表示用克隆音色。

## 失败处理

- `audio_key` 无效或不属于当前用户：请用户重新上传，不要换一个 key 重试。
- 音色服务返回 5xx：这是上游临时故障，**不要重试同一个调用**，告诉用户音色服务暂时不可用，可以稍后再试或先用系统音色。
- 录音太吵、太短、几乎没有人声：说明具体问题，请用户重录（安静环境、10 秒以上、正常音量、正常语速）。
- 用户对试听不满意：优先建议换一段更干净的录音重录，而不是反复调参数。

## 不要做的事

- 不要对同一个失败的调用反复重试。
- 不要用中文给音色命名，也不要用中文写 `preview_text`。
- 不要在克隆成功后自动创建角色，必须等用户确认。
- 不要把 `audio_key`、`voice_profile_id` 这类内部标识展示给用户。
